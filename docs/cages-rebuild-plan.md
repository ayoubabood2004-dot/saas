# إعادة بناء نظام الأقفاص — الأقفاص صفوفاً لا رسمة

**التاريخ**: ٢٧/٩/٢٠٢٦ · **قرار المالك**: «لا، أريد إعادة بناء صح — سويلي خطة كاملة
للأوبس حتى ينفذها» (بعد عرض الخيارين: ترقيع `docs/cages-plan.md` أو إعادة بناء).
**بوابة**: قبل أول هجرة يؤكَّد الفهم مع المالك بسطر، والدمج لـmain بكلمته وحدها.

**العلاقة بـ`docs/cages-plan.md`** (تدقيق النظام الحالي — يُقرأ أولاً): هذه الخطة
تحلّ محل بنوده ك١ وك٣–ك٧ (تموت عللُها بالبنية)، **وتحمل** ك٢ (الهوية) وك٨
(التنظيف والقياس) بنودَها كما هي — انظر §٩ للتغطية بنداً بنداً.

**كيف صُنعت**: أربعة تصاميم مستقلة (القاعدة/الترحيل/الواجهة/الإشغال)، كلٌّ هوجم
عدائياً، ثم فحصٌ عرضاني حسم ٢١ تنازعاً بينها. ما يلي هو **الحكم النهائي الملزم** —
حيث تعارض تصميمُ منطقةٍ مع هذه الوثيقة، هذه الوثيقة تفوز.

> **التنفيذ (٢٨/٩، بكلمة المالك «نفّذها»)** — `0219_cages_first_class.sql`،
> `0220_cage_backfill.sql`، والمتجر `src/components/cage3d/store.ts`. انحرف عن
> الخطة بثلاثة مواضع مقصودة، كلٌّ أبسطُ وأضيقُ سطحاً:
> 1. **كتابةٌ واحدة لا أربع**: `cage_layout_apply(p_clinic, p_ops)` دفعةُ عملياتٍ على
>    صفوفٍ بعينها بمعاملةٍ واحدة (غرف/أقفاص: إدراج/تحديث/حذف، وترقيمٌ بمرحلتين
>    داخلها) بدل RPC للترقيم وأخرى لتحريك الغرف. الختمُ `p_clinic` من `my_workspace()`
>    لحظةَ الترطيب (ق٤).
> 2. **النصُّ يبقى مصدرَ الإقامة و`cage_id` يُشتقّ بالخادم**: محفّز `admissions_cage_link`
>    يشتقّ المعرّفَ من `admissions.cage` بكلّ كتابة ويفحص الإشغال بالاسم، ويرفض كتابةَ
>    المعرّف مباشرةً (ق١١+ق١٣ ببابٍ واحد). فكلُّ الشاشات القائمة والحزمُ القديمة تبقى
>    تعمل بلا تغيير، و`assign_admission_cage` (ق٣) لم تلزم.
> 3. **قراءةُ الأقفاص بطلبٍ واحد لكلّ جدول** (السقفان ٤٠/٤٠٠ تحت حدّ الألف) لا
>    `allPages`، ومتجرُ الشاشة يرتدّ لآخر ما أكّده الخادم عند أيّ رفض ويقوله.
> وحارسٌ زاد على الخطة أمسكه الفحص: **القفصُ داخل حدود غرفته** (`cage_outside_room`
> / `room_cuts_cages`) — تصغيرُ غرفةٍ من جهازٍ وإضافةُ قفصٍ بخلاياها من آخر بنفس
> اللحظة كانا سيتركان قفصاً بلا غرفة يُفشل كلَّ حفظٍ بعده.
> القرارات الافتراضية المأخوذة (§١٠): إجلاسُ الأقدم (المقيس صفرُ ازدواج فلا أثر)،
> السقفان ٤٠/٤٠٠، `admissions.cage` باقٍ، سجلُّ الترتيب ولافتةُ «ترتيب محفوظ على هذه
> الحاسبة» أُزيلا، والمفتاحُ القديم بالأجهزة لا يُقرأ ولا يُمسح (التجريبيُّ يُحوَّل صفوفاً).

## ١) الفكرة بسطرين

اليوم التخطيطُ كلُّه نصٌّ واحد بعمود `clinic_prefs.cage_layout` — فكلُّ تعديلٍ
حفظُ رسمةٍ كاملة، وكلُّ آلة النسخ والمرايا والتعارضات موجودة لخدمة ذلك، وهي
مصدرُ العبور بين العيادات. بعد اليوم: **القفص سجلٌّ مثل المنتج** — جدولا
`cage_rooms` و`cages` كلُّ صفٍّ مختومٌ بعيادته، والإقامة تشير للقفص بمعرّفه
(`admissions.cage_id`)، والإشغالُ يفرضه فهرسٌ فريد. أسوأُ كتابةٍ ضالّة تفسد
صفاً واحداً يُرى ويُصلَّح — لا دهسَ عمل شهرٍ كامل.

## ٣) عقد الأخطاء والأسماء — المرجع الواحد

كلُّ خطأ يُرمى بـ`raise exception '<الرمز>'` + hint عربي؛ الواجهة تميّزه بالرمز
وتترجم بمفتاح i18n واحد؛ **المرآة التجريبية تفرض القائمة كاملة بنفس الرموز**
(قاعدة payrollDemo — فحوص المنطق تجري عليها):

| الرمز | يرميه | الرسالة (hint) | مفتاح i18n |
|---|---|---|---|
| `cage_occupied` | assign / محفّز التوافق | «القفص {code} بيه {name} — اختر قفصاً ثانياً، أو طلّعه/انقله أولاً» + detail JSON `{pet_name, cage_code, admission_id}` | `cages.occupiedBy` |
| `cage_gone` | assign | «القفص انحذف من التخطيط — حدّث الصفحة» | `cages.cageGone` |
| `admission_gone` | assign | «الإقامة انتهت أو انحذفت — حدّث الصفحة» | `cages.admGone` |
| `cage_occupied_delete` | حارس حذف القفص | «القفص بيه نزيل — رقّده بقفص ثاني أو خرّجه قبل الحذف» | `cages.delOccupied` |
| `room_not_empty` | حارس حذف الغرفة | «فرّغ الغرفة من أقفاصها أولاً» | `cages.roomNotEmpty` |
| `code_twin` | محفّز التحقق | «الرمز {code} موجود بقفص ثاني — القفص له رمز واحد» | `cages.codeTwin` |
| `too_many_rooms` / `too_many_cages` | محفّزا السقف | «وصلتوا سقف الغرف (٤٠)…» / «…الأقفاص (٤٠٠)…» — **الرقمان سؤال مالك** | `cages.capRooms/capCages` |
| `cage_cross_clinic` / `room_cross_clinic` / `clinic_frozen` | محفّزات التحقق والتجميد | «…مو من نفس العيادة — حدّث الصفحة» | `cages.crossClinic` |

where status = 'active' and cage_id is not null` — الفحوص تفتش عنه بالاسم.

## ٤) الدفعة ١ — هجرة `0219_cages_first_class.sql` + الحزمة

**البند الأول قبل كل شيء: توسيع `supabase/tests/harness.sql`** — لا يحتوي
admissions ولا `admission_status` إطلاقاً (grep = 0)، فالهجرة نفسها لا تنزل
بالحزمة بدونه: النوع + جدولا admissions/pets بشكلٍ رخو + fixtures `adm1/adm2`
وpet لكلٍّ بعيادتي `$C1/$C2` + **عيادتان جديدتان `$C3/$C4`** بكادر وprefs
(لفحوص الخردة واللافتة).

**DDL** (الأعمدة ممسوحة من `cageLayout.ts` — LayoutRoom/LayoutCage v2؛
لا `numeric(p,s)`):

```sql
create table if not exists cage_rooms (
  id         uuid primary key default gen_random_uuid(),
  clinic_id  uuid not null default auth_clinic() references auth.users(id) on delete cascade,
  legacy_id  text,                                   -- معرّف الغرفة بالنص القديم؛ يُسقط في 022X
  name       text not null check (length(btrim(name)) between 1 and 60),
  x integer not null default 0 check (abs(x) <= 1000),
  z integer not null default 0 check (abs(z) <= 1000),
  w integer not null default 1 check (w between 1 and 50),
  d integer not null default 1 check (d between 1 and 50),
  door_side  text check (door_side in ('front','back','left','right')),
  door_at    integer check (door_at >= 0),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
create index if not exists cage_rooms_clinic_idx on cage_rooms(clinic_id);

create table if not exists cages (
  id         uuid primary key default gen_random_uuid(),
  clinic_id  uuid not null default auth_clinic() references auth.users(id) on delete cascade,
  room_id    uuid not null references cage_rooms(id) on delete restrict,
  code       text not null check (length(btrim(code)) between 1 and 24),
  x integer not null default 0 check (abs(x) <= 1000),   -- إحداثيات عالمية كما اليوم
  z integer not null default 0 check (abs(z) <= 1000),
  color      text check (color is null or length(color) <= 24),
  facing     smallint not null default 0 check (facing between 0 and 3),
  level      smallint not null default 0 check (level between 0 and 1),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
create index if not exists cages_clinic_idx on cages(clinic_id);
create index if not exists cages_room_idx   on cages(room_id);
create unique index if not exists cages_code_uq on cages(clinic_id, lower(btrim(code)));

alter table admissions add column if not exists cage_id uuid references cages(id) on delete set null;
create index if not exists adm_cage_idx on admissions(cage_id);  -- db-guard يرفض الجزئي كتغطية FK
```

**RLS**: أربع سياسات مفكّكة لكل جدول، **ملكيّةً وحدها** بصيغة initplan
(`clinic_id = (select auth_clinic())`) — لا شرطَ آخر بأي سياسة (درس 42P17)؛
`enable + force row level security`. دخول المشغّل يعمل تلقائياً (auth_clinic
بفرع المنصّة هي نفسها بالسياسة والقيمة الافتراضية).

**المحفّزات** (كلُّ definer بـ`set search_path`، وكل invoker يحرس
`current_user='authenticated'` وحده):
- تجميد `clinic_id` (invoker) ⇒ `clinic_frozen`. لا يُجمَّد غيره.
- تحقّق التقاطع (definer + فحص صريح): `cages.room_id` غرفة بنفس العيادة ⇒
  `room_cross_clinic`؛ `admissions.cage_id` قفص بنفس العيادة ⇒ `cage_cross_clinic`.
- حراسة الحذف (definer): قفص عليه إقامة نشطة ⇒ `cage_occupied_delete` (مع
  `for key share` على صفوف الإقامة لسدّ سباق الكتابة المباشرة)؛ غرفة فيها
  أقفاص ⇒ `room_not_empty`.

  `too_many_rooms/too_many_cages`.

  `update admissions set cage = new.code where cage_id = new.id and status = 'active'`
  — يرفع `vp.cage_mirror` (ق١٢).
- `audit_all` على الجدولين (نمط 0152) — التدقيق يصير قفصاً قفصاً.
- محفّز تجميد `cage_id` على admissions (ق١٣).
- توسيع محفّز 0070 ليطلق على تغيّر `cage_id` ويتخطّى `vp.cage_mirror` (ق١٢).

**RPCs** (تواقيع §٢ ق٣/ق٥/ق٢٠ حرفياً + `create_cages_from_codes` §٦·٣؛
`revoke from public, anon` و`grant to authenticated`؛ دوال الترحيل الداخلية
تُمنع عن authenticated **وservice_role يُمنح صراحةً** ما يحتاجه سكربت التراجع).

**فحوص run.sh** — تدخل 0219 قائمة WAVE، وكلُّ ادّعاء RLS/دور عبر `_rls_try`

## ١٠) يوم −١: القياسات واستبيان المالك

**استعلامات بوابة الدم** (على الإنتاج، ناتجها يُحفظ أساس مقارنة):
أطوال الرموز والأسماء (ضد checks ≤٢٤/≤٦٠)، مدى الإحداثيات (ضد ±١٠٠٠)،
توائم v2 داخلية، `clinic_id is null` بالإقامات النشطة، ازدواج الإقامات النشطة
(استعلام تصميم الإشغال §٣ بالمطبّع الموحّد ق١٠)، خلايا مزدوجة (ق٢٠)،
هل `__changed.cage_layout` كامل أم `[large:N]` (ق١٥).

**استبيان المالك — سبعة أسئلة بجلسة واحدة**:
١) تأكيد قراءة «إعادة بناء صح». ٢) قاعدة إجلاس الازدواج (الموصى: الأقدم).
٣) أرقام السقوف (الموصى: ٤٠/٤٠٠). ٤) مصير `admissions.cage` النصي بعد
التنظيف (الموصى: يبقى تاريخاً). ٥) ك٥: مفتاح الجهاز القديم — مسح صامت أم
عرض أخير؟ ٦) فقدان «الاسترجاع بضغطة» مقابل الأرشيف اليدوي — موافق؟
٧) طول نافذة التنظيف (الموصى: أسبوع نظيف بالعدّاد).

## ١١) النشر البشري (عيادات حية)

1. **يوم −١**: القياسات + الاستبيان + رسالة واتساب للعيادات السبع (مسودة
   تصميم الإشغال §٥ — تُحرَّر ولا تُرسل آلياً): «تحسين بغرفة الأقفاص؛ إذا
   حاولت تسكّن بقفص بيه ساكن النظام يكَلّك باسمه؛ التعديل يخزن لحاله فوراً
   بلا زر حفظ؛ حيوانات چانت مخفية بالغلط راح تبين بشريط أصفر».
2. **ليلة النشر**: 0219 + 0220 بساعة هادئة، التقاط تقريري الترحيل ومقارنتهما
   بالقياس.
3. **صبيحتها**: دفعة الواجهة (تقليص نافذة القطع لساعات — خلالها حفظُ تخطيطٍ
   من حزمة قديمة يُرفض واللافتة القديمة تعرض وعدها الكاذب د٢: كلفة معلنة
   مقبولة بقِصَر النافذة).
4. **نفس اليوم**: مكالمة العيادتين الشاكيتين («الي شفتوه انحل من جذره») +
   مرافقة عيادتي اللا-تخطيط على زر «اعتمد أقفاصي».
5. **بعد أسبوع**: قياس §١٢، ثم بوابات §٨، ثم 022X بكلمة المالك.

**ما قد يربك الكادر** (يُستبق بالرسالة): اختفاء حوار التعارض («ماكو تعارض
بعد»)، الرفض المسمّى الجديد («مو عطل — حماية»)، ازدواجات الأمس تطفو بشريط
«بلا قفص»، الترقيم صار فورياً بلا «تراجع بإغلاق الصفحة».

## ١٢) قياس ما بعد النشر (القياس يحكم على الإصلاح)

صفر كتابات على العمود القديم بعد دفعة الواجهة؛ صفر ازدواج نشط؛ اليتامى
ينحسرون (هدف: صفر بالسبع، هبوط مستمر عند عيادتي الاعتماد)؛ صفر صفوف
audit على cages/cage_rooms عيادةُ فاعلها ≠ عيادة الصف؛ صفر actor=null على
الجدولين؛ عدّاد `cage_layout_moved` ينطفئ. النتائج تُدوَّن بذيل هذه الوثيقة.

## ١٣) قواعد التنفيذ الثابتة

قبل كل دفعة: `npm run lint && npm run build && PGBIN=… bash
supabase/tests/run.sh`. كل هجرة تدخل WAVE وتنعاد بلا أثر ثانٍ. كل ادّعاء
RLS/دور عبر `_rls_try`. المرآة التجريبية تفرض نفس الحرّاس بنفس الرموز.
رسالة الدفعة تشرح الجذر. لا تُسكِت حارساً — أصلح. التفاصيل الكاملة لكل
منطقة (DDL الكامل، خريطة حقول الترحيل، نصوص fixtures، جدول مستهلكي
الترتيب) موجودة بمخرجات التصميم — وهذه الوثيقة تحسم كلَّ ما تنازعت فيه.
