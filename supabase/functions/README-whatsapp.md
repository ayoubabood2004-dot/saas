# واتساب الرسمي (Meta Cloud API) — الربط والتشغيل

الطريقة الحالية (روابط `wa.me`) **تبقى كما هي ولا تُحذف أبداً**: مجانية، بلا
حساب، وبلا خطر حظر. هذه الوثيقة تخصّ الطريقة الرسمية الاختيارية، وهي تعمل
**لكل عيادة على حدة**: العيادة التي لا تربط رقماً لا يتغيّر عندها شيء إطلاقاً.

المفتاح الذي يقرّر أي طريقة تعمل ليس زراً، بل صفّ في `wa_accounts`:
`wa_is_connected()` ⇒ `false` لكل عيادة لم تربط رقماً.

---

## البنية

| الجزء | المكان | ينتشر كيف |
|---|---|---|
| نقطة الاستقبال | `api/wa-webhook.ts` + إعادة توجيه `/wa-webhook` في `vercel.json` | تلقائياً مع كل دفعة إلى `main` (Vercel) |
| الجداول | `supabase/migrations/0111_wa_cloud_api.sql` | لصق يدوي بمحرّر SQL |

**تطبيق ميتا واحد للمنصّة كلها** — لا تطبيق لكل عيادة. وعليه: رمز تحقّق واحد،
وسرّ تطبيق واحد بيد المنصّة، ورابط ويبهوك واحد. وتوجيه كل رسالة إلى عيادتها
يتمّ عبر `phone_number_id` المسجَّل مسبقاً في `wa_accounts` — لا عبر جسم الطلب.

**ملكية الحسابات**: حافظة الأعمال وحساب واتساب والرقم تبقى **باسم العيادة**،
والمنصّة تربطها بتطبيقها فقط. أن تُسجَّل حافظة عيادةٍ باسم المنصّة يجعلها مالكة
هوية تجارية ليست لها.

## خطوات التشغيل بالترتيب

### ١) الهجرة
الصق `0111_wa_cloud_api.sql` في Supabase → SQL Editor → Run.

تحقّق: `select wa_is_connected();` ⇒ `false` (لا عيادة مربوطة بعد — وهذا الصحيح).

### ٢) متغيّرات البيئة على Vercel
Vercel → Project → Settings → Environment Variables (بيئة **Production**):

| المتغيّر | من أين |
|---|---|
| `WA_VERIFY_TOKEN` | ولّده أنت: `openssl rand -hex 32` |
| `WA_APP_SECRET` | Meta App Dashboard → App Settings → Basic → App Secret → Show |
| `SUPABASE_URL` | اختياري — يُقرأ `VITE_SUPABASE_URL` الموجود أصلاً إن غاب |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Project Settings → API → `service_role` |

`SUPABASE_SERVICE_ROLE_KEY` **خادميّ بحت**. لا يصل المتصفّح: Vite لا يكشف إلا
المتغيّرات التي تبدأ بـ`VITE_`. لا تسبقه بهذه البادئة أبداً.

بعد الإضافة: أعد النشر (Redeploy) حتى تُقرأ القيم.

### ٣) اختبار المصافحة قبل لمس شاشة ميتا
```bash
curl -i "https://doctorvet.vet/wa-webhook?hub.mode=subscribe&hub.verify_token=<TOKEN>&hub.challenge=ping123"
```
المتوقّع: `200` وجسم الرد **`ping123`** حرفياً — بلا أقواس ولا JSON ولا سطر جديد.

وفحصٌ سالب يجب أن يفشل:
```bash
curl -i "https://doctorvet.vet/wa-webhook?hub.mode=subscribe&hub.verify_token=wrong&hub.challenge=ping123"
```
المتوقّع: `403`.

إن رجع HTML بدل `ping123` فتأكّد أن إعادة التوجيه `/wa-webhook` ما زالت
**قبل** الالتقاط العام `/(.*)` في `vercel.json`. النداء المباشر على
`/api/wa-webhook` **لا يعمل** — الالتقاط العام يبتلعه ويعيد `index.html`،
وهذا سبب وجود سطر إعادة التوجيه الصريح.

### ٤) شاشة ميتا — تكوين Webhooks
- **عنوان URL الاستدعاء**: `https://doctorvet.vet/wa-webhook`
- **تحقق من الرمز**: قيمة `WA_VERIFY_TOKEN` نفسها
- اضغط **تحقق واحفظ**
- ثم **Webhook fields → Manage** → فعّل حقل **`messages`** (يجلب الرسائل
  الواردة وتحديثات الحالة معاً)

### ٥) الرقم
1. سجّل الرقم داخل حساب واتساب الأعمال، وخذ موافقة ميتا على اسم العرض.
2. **اشترك التطبيق بحساب الواتساب**: `POST /{WABA_ID}/subscribed_apps`.
   إن نُسيت هذه الخطوة يبدو كل شيء ناجحاً ولا يصل أي حدث أبداً.
3. اربط الرقم بالعيادة (كمشغّل المنصّة):
   ```sql
   select admin_wa_link_account(
     '<CLINIC_UUID>', '<PHONE_NUMBER_ID>', '<WABA_ID>',
     '<الرقم كما يظهر>', '<اسم العيادة المعتمد>');
   ```

### ٦) الاختبار الحيّ
أرسل رسالة من هاتفك إلى الرقم، ثم:
```sql
select received_at, signature_ok, note, routed_clinic from wa_webhook_events
order by received_at desc limit 5;
select direction, peer_phone, msg_type, body, status from wa_inbox
order by created_at desc limit 10;
```
`note = 'unknown_number'` ⇒ الرقم لم يُربط بعد (الخطوة ٥٫٣).
`signature_ok = false` ⇒ `WA_APP_SECRET` خاطئ أو من تطبيق آخر.

## تحذير لا يُستهان به

تسجيل رقم على Cloud API **يزيله نهائياً من تطبيق WhatsApp Business على
الهاتف**، وسجلّ محادثاته هناك يضيع. لا رجعة. الرقم بعدها يعيش داخل السستم
وحده. **جرّب على شريحة جديدة أولاً** — لا على رقم العيادة الحيّ.

## ما لم يُبنَ بعد

استقبالٌ فقط. الإرسال عبر Cloud API (`wa-send`) وصندوق الوارد بالواجهة وتنزيل
الوسائط مراحل تالية. وقبل أي إرسال حقيقي يجب أن يُفرض **حدّ الحصة على الخادم**
وقاعدة نافذة الـ٢٤ ساعة — وإلا جرت محاسبة ميتا بلا عدّاد.

## غير مؤكَّد (وثائق ميتا كانت محجوبة وقت البناء)

مهلة الردّ بالثواني، ومدّة إعادة المحاولة، وحدود الحسابات غير الموثّقة، وأشكال
الحمولات لأنواع الرسائل غير النصّية. ولهذا تحديداً يُخزَّن الظرف الخام في
`wa_webhook_events`: أول أسبوع تشغيل حقيقي هو ما يكشف الأشكال الفعلية.
