# جسر المختبر — المُستقبِل الصغير (lab-bridge)

برنامج صغير يشتغل على أي حاسوب **قرب جهاز التحاليل**، يقرأ نتائج الجهاز
ويرسلها تلقائياً إلى **صندوق المختبر** داخل نظام doctorVet — عبر الشبكة (LAN)
أو الإنترنت. الجهاز يقدر يكون بغرفة والسستم بغرفة ثانية، والنتائج توصل بنفسها
بلا كتابة ولا واير طويل.

```
جهاز التحاليل  ──(شبكة/سريال)──▶  المُستقبِل (هذا البرنامج)  ──(إنترنت آمن)──▶  صندوق المختبر بالسستم
```

---

## المتطلبات

- حاسوب (ويندوز/ماك/لينكس) قرب الجهاز، متصل بنفس الشبكة.
- **Node.js 18 أو أحدث** (تحميل مجاني من nodejs.org).
- **الأسهل:** نزّل الملفين مباشرة من السستم — **الإعدادات ← ربط أجهزة المختبر ←
  أضف جهاز ←** زر **«برنامج المُستقبِل»** (ملف `lab-bridge.mjs` واحد ذاتي
  الاكتفاء) وزر **«ملف الإعداد»** (`lab-bridge.config.json`). حطّهم بمجلد واحد.
- بديل للمطوّرين: هذا المجلد (`tools/lab-bridge`) يحتوي نفس البرنامج مقسّماً
  (`lab-bridge.mjs` + `framing.mjs`) مع محاكي واختبار.

## التشغيل (٣ خطوات)

1. حط ملف `lab-bridge.config.json` بنفس مجلد هذا البرنامج.
2. افتح موجّه الأوامر (Terminal) بالمجلد وشغّل:

   ```bash
   node lab-bridge.mjs
   ```

   راح تشوف: `▶ المُستقبِل «...» يستمع على 0.0.0.0:9100`.
3. بإعدادات جهاز التحاليل (قسم LIS / Host / Network)، حط:
   - **عنوان المضيف (Host IP):** عنوان هذا الحاسوب على الشبكة (مثال `192.168.1.20`).
   - **المنفذ (Port):** `9100`.

شغّل تحليل — النتيجة راح توصل صندوق المختبر داخل أي سجل حيوان، واضغط
«استقبال» لتربطها بالحيوان الصحيح.

> للتأكد قبل الجهاز الحقيقي: من الإعدادات اضغط **«تجربة»** — راح تنزل رسالة
> نموذجية بالصندوق فوراً.

## الأوضاع (Modes)

يُضبط الوضع من `mode` بملف الإعداد:

| الوضع | متى تستخدمه |
|------|-------------|
| `tcp-listen` (الافتراضي) | الجهاز يرسل النتائج للشبكة. المُستقبِل يستمع على منفذ، والجهاز يُوجَّه لعنوان الحاسوب. **هذا الأنسب للربط بين الغرف عبر LAN.** |
| `tcp-connect` | الجهاز نفسه يستمع (يعمل كخادم). المُستقبِل يتصل به على `host:port`. |
| `serial` | ربط مباشر بكيبل USB/RS-232. يحتاج `npm i serialport` وتحديد `serialPath` (مثل `COM3` أو `/dev/ttyUSB0`). |

يتعرّف المُستقبِل على لغة الجهاز تلقائياً (`framing: "auto"`): **HL7 (MLLP)**،
**ASTM E1381/E1394**، أو نص أسطر بسيط — ويرد ACK لأجهزة ASTM تلقائياً حتى لا
تلغي الإرسال.

## ملف الإعداد (مثال)

```json
{
  "url": "https://YOUR-PROJECT.supabase.co",
  "anonKey": "…anon key…",
  "token": "…الرمز السري للجهاز…",
  "device": "جهاز CBC — غرفة المختبر",
  "mode": "tcp-listen",
  "host": "0.0.0.0",
  "port": 9100,
  "framing": "auto",
  "baudRate": 9600
}
```

كل القيم تقدر تنضبط أيضاً بمتغيرات البيئة:
`LAB_BRIDGE_URL`، `LAB_BRIDGE_TOKEN`، `LAB_BRIDGE_MODE`، `LAB_BRIDGE_PORT`، …

## التجربة بلا جهاز

شغّل المُستقبِل، وبنافذة ثانية شغّل محاكي الجهاز:

```bash
node sim-analyzer.mjs astm      # أو hl7 أو generic
```

راح يرسل تحليل نموذجي للمُستقبِل، والمُستقبِل يرسله للسحابة.

## اختبار المطوّر (شامل، بلا سحابة ولا جهاز)

```bash
node test-bridge.mjs
```

يشغّل سحابة وهمية + المُستقبِل الحقيقي + المحاكي بلغات HL7/ASTM/نص، ويتأكد أن كل
رسالة وصلت سليمة.

## الأمان

- **الرمز (token)** هو هوية الجهاز الوحيدة — لا تشاركه. من فُقد أو تسرّب، ألغِ
  الجهاز من الإعدادات وأضف واحداً جديداً؛ القديم يتوقف فوراً.
- الاستقبال السحابي يقبل الرمز فقط ويحطّه بصندوق عيادتك — لا يقدر يقرأ أو يكتب أي
  شيء ثاني بالسستم.
- الرسائل تظهر «جديدة» بالصندوق ولا تُسجَّل على أي حيوان إلا بعد ما الطبيب يضغط
  «استقبال» — القرار دائماً بيد الطبيب.
